# User Simulation

Synthetic UX testing for your **live web app**, from Claude Code. Give it a URL, answer three quick
questions, and get back a one-page action summary — what to fix, what users hit, how they felt —
with links to the full reports.

## Install

In Claude Code:

```
/plugin marketplace add PabloManzoni/user-simulation
/plugin install user-simulation@pablom-plugins
/reload-plugins
```

That's it. **Nothing else to install** — it uses the browser you already have: the built-in browser
of the Claude desktop app, or Claude in Chrome (`/chrome` in Claude
Code). If you already have Playwright MCP set up, it uses that.

## Use

```
user simulation https://your-app.com
```

(or `/user-simulation:user-simulation https://your-app.com`)

1. **What do we run?** — User simulation · Heuristic review · Both
2. **Which users?** — Inferred (it builds 3 realistic users from your site) · Your own profile
3. **What scope?** — One screen (the one at the URL) · A flow → it proposes tasks, you pick one or
   type your own

Then it runs on its own. No more questions.

## What you get

A short summary in chat (also saved as `user-simulation-tests/<date>-<domain>-summary.md`):

> **In one line:** 2 of 3 users booked a court; checkout's "Process" button stopped the first-timer.
>
> **🎯 What to do**
>
> | # | Action | Fixes | Seen by | Criticality |
> |---|--------|-------|---------|-------------|
> | 1 | Rename "Process" to "Pay $120" on checkout | F1 | U1 U2 · 🔍 | 🔴 High |
> | 2 | Show court availability before asking for login | F2 | U1 U3 | 🟠 Medium |
>
> **🔎 What we found** · **💭 How they felt** · **🧭 Friction map** · **✅ What works**
>
> ---
> **👤 Users:** U1 · First-timer · U2 · Regular · U3 · Club admin
> **📄 Reports:** Consolidated · Heuristic · Profiles

Every row links back to the full reports — those stay complete and detailed (per-screen
walkthroughs, emotional arcs, evidence quotes, per-persona ratings).

### Two lenses

| | **Experience** (simulation) | **Inspection** (heuristics) |
|---|---|---|
| The question | *How does it feel to use this?* | *Does it violate known usability principles?* |
| Who looks | Synthetic users, in character | An expert evaluator + three rater personas |
| Full report | Step-by-step run: friction, doubt, emotion, where they give up | Prioritized findings against Nielsen's 10 heuristics |

### How it works

An orchestrator (the skill) drives the browser and delegates judgment to focused subagents with
clean context:

- **Experience**: `synthetic-screen-evaluator` reacts to one screen at a time in character;
  `synthetic-flow-synthesizer` writes each run's report; `synthetic-profile-generator` builds each
  inferred user; `synthetic-autopilot-synthesizer` consolidates the runs.
- **Inspection**: `heuristic-persona-generator` builds the three rater personas,
  `heuristic-expert-evaluator` detects violations, three `heuristic-persona-rater` calls score them,
  `heuristic-report-synthesizer` writes the report.
- **Summary**: `summary-synthesizer` reads every full report and distills the one-page action
  summary.

Methodology: [frameworks/synthetic-users.md](frameworks/synthetic-users.md) (experience) and
[frameworks/heuristic-test.md](frameworks/heuristic-test.md) (inspection — Nielsen & Molich 1990,
Nielsen 1994, Nielsen & Mack 1994). Example profile:
[examples/profiles/diego-nakamura-b7k.md](examples/profiles/diego-nakamura-b7k.md).
